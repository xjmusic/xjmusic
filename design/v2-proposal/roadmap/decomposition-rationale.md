# Master decomposition: rationale

`master.json` starts from the judged winner, `candidate-risk-first`, and fixes every defect the three judges listed for it, then grafts the ideas they singled out from `candidate-contract-first` and `candidate-thin-slices`. After audit rounds 1 and 2 (below) the result is **63 epics, 276 tasks, 888 engineer-days** (P0 71, P1 199, P2 194, P3 125.5, P4 105, P5 93, P6 85, P7 15); 137 S, 116 M, 21 XS, 2 L tasks; 734 blocked-by edges of which 197 cross a phase; epic edges are computed from the task edges, so the parent-issue waterfall is exactly the task waterfall (zero phantom, zero unmirrored). `validate.py` prints OK.

## The shape

Risk-first's spine is kept: paperwork, rights inventory and dated decision records in Phase 0; engine 2.0 built on fixed port regressions; a headless station that must pass a listening gate before any UI; Commons alongside Play mode; sessions on top of the engine's foundation seam; Make-mode parity last. Three ordering corrections change the feel of the plan:

1. **Fixes before goldens.** Determinism goldens are captured after the delta/crescendo, persistence-window, store-put and voice-name fixes (and after the Java tests are mined), so they encode the reference behavior once. The RNG swap waits on the delta-arc fix because it owns one of the seven generator sites; per-engine 128-bit ids are their own small task that needs only the RNG primitives (the id prefix is drawn from the chain seed so replays stay byte-identical), so `run_cycle` does not wait on the whole determinism chain. The goldens are captured over the richer Beat/Detail fixture, after every port fix.
2. **Thin slices first.** `xj-station` makes sound at day 33 (`p2-stn-first-sound-play-minimal`: wrapper, payload, decode, clock, voices, cpal), before buses, FX, control, cues or variants. The surface starts as one pad with preview and landing time. Make mode starts as one renamed instrument reopened in Java.
3. **Sessions never depend on Link.** Publish/consume runs on the `session` clock and the Rust follow test; the Link epoch bridge is consumed only by the real-gear duet. The GPL binding fork moves from Phase 0 to Phase 2, and the Phase 0 spike runs rusty_link as published, on company machines.

## Judgment calls

- The **Phase 2 gate blocks the shell skeleton**, so no UI work starts before the station is judged good enough; Phase 1 and the non-engine Phase 2 crates still start from the spike, and Phase 6 starts when the shell exists.
- The **go/no-go gate** gates Java maintenance mode and the shell, not the Rust workspace, so the UI toolkit spike never serializes Phase 2.
- **Rust CI from Phase 0** stays (R13 says so literally); **CLI signing moves to Phase 3** (R13 says signing is set up in Phase 3), leaving checksummed CLI releases in Phase 2.
- The **Make-button handoff to Java** is not in the proposal's text, but it is the only way to honor "Make mode is one click away" while 2.0.0 ships no editors and Java is the editor of record.
- `xj_engine_reload_content` is a **new ABI name**, introduced because 05 assumes a reload the engine does not have; it follows the register's conventions and is additive.
- Release epics keep **large fan-in** (e1-engine-release-ci 10, e3-packaging 11): every one is a real "all exit conditions green" dependency rather than a hub for convenience.
- Seed packs are **two tasks for Lofi and Deep House** and one each for Hero's Journey and Ambient Flow, and the starter pack is sized at M/6 engineering (commissioning is content work the roadmap does not size).
- 873 days (about 41 engineer-months) is above 09's 23.5–33.5 EM band; the roadmap's own ±50% uncertainty and the cost of 1–10-day issue granularity account for the gap. The per-phase proportions do not all track the band: Phase 1 is 194 days (about 9 EM against 09's 3–4) because the grounded port-regression and determinism findings (seven RNG sites, eleven divergent behaviors, the missing segment serializers and the ABI hardening) are engine work 09 did not know about; Phase 6 is 85 days (about 4 EM against 09's 5–8) because the shared CRUD service, undo stack and canvas component absorb most of the ~6,000 lines of Java FXML and controllers, and the two largest editor modes are sized L; the remaining gap sits inside 09's ±50%.
